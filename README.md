# mc_bot —— KiraAI 的 Minecraft 身体

给云端 QQ 机器人（KiraAI）接一个跑在本机的 mineflayer 身体。游戏里发生的事会进到**同一个 QQ 会话**，所以它玩 MC 时用的是同一份人格和记忆。

## 一键启动

双击 **`启动.bat`**，或命令行 `node start-all.js`。Ctrl-C 三个进程一起关。

## 当前状态

**能做的**：进服、走路、砍树、挖矿、跟随、说话、看背包、读方块。叫名字会应，空闲时会自己决定做什么，能规划 2-5 步连着做。

**当前不可用**：她**不会脱离战斗，也从来没有成功睡过觉**。前者是 `_tick()` 里低血量分支直接 `return`，后者是 `_sleepTick()` 的变量遮蔽导致必抛异常。另外决策链会在云端不可达时静默停摆（实测连续 3 小时什么都没做）。

> **下一步不是继续修这版，而是按 [真人化重构方案.md](真人化重构方案.md) 重写行为层**。方案里先列出 4 个必须立刻修的止血点，再给完整的感知/仲裁/任务栈架构。动手前先读它。

## 架构

```
本机 Windows                          阿里云 120.26.117.155
┌───────────────────────┐            ┌──────────────────────────┐
│ ViaProxy :25568       │            │ KiraAI 容器 :5267        │
│   ↑26.1    ↓26.2正版  │            │  └ mc_bridge 插件        │
│ mc_bot (mineflayer)   │  HTTP轮询  │      ├ /poll 取任务      │
│   └ link.js ──────────┼───────────►│      ├ /result 回报+事件 │
└───────────────────────┘  SSH隧道   │      └ publish_notice()  │

```

**为什么用 HTTP 轮询而不是 WebSocket**：KiraAI 的插件 WebSocket 路由当前不可用（所有 WS 升级请求返回 403）。改用 HTTP 后不需要任何 KiraAI 侧改动，代价是多了 3 秒轮询间隔，实测工具调用仍在 1 秒内完成。

1. **ViaProxy**（协议翻译，本机）
   ```bash
   cd runtime/viaproxy && node run.js
   ```

2. **SSH 隧道**（把云端 5267 映射到本机 15267）
   ```bash
   ssh -N -L 15267:127.0.0.1:5267 -i C:/Users/初雪/.ssh/codex_vps_ed25519_v2 \
       -o ServerAliveInterval=30 root@120.26.117.155
   ```

3. **mc_bot**
   ```bash
   cd mc_bot && node src/index.js
   ```

成功标志：bot 日志出现 `[link] connected to ...`，云端 `/api/plugin/mc_bridge/status` 返回 `"connected": true`。

## 四个必须记住的坑

1. ViaProxy 的 CLI 参数 `--auth-method ACCOUNT` **不生效**，必须 `java -jar ViaProxy.jar config viaproxy.yml`
2. 不设 `fake-accept-resource-packs: true`，mineflayer 永远卡在 configuration 状态
3. Java 读不了中文绝对路径下的 jar，`cwd` 必须是 jar 所在目录
4. 同一账号不能同时在官方客户端和 bot 上在线，会互相踢下线

`runtime/viaproxy/saves.json` 含微软账号完整令牌，可直接用于登录。已在 `.gitignore`，切勿提交或外传。

## 断线恢复

`start-all.js` 里 SSH 隧道带自动重连（断线 3 秒后重试），mc_bot 的链路退避上限 15 秒。
实测断网恢复后约 1 分钟自动回到 `connected: true`，不需要手动干预。

## 自主玩耍

bot 在没有指令时也能自己决定做什么，由 `src/intent.js` 驱动：

- **谁来决策**：云端模型。身体空闲时发一条 `intent` 事件，带上血量、饥饿、坐标、昼夜，
  模型据此挑一个模式（砍树/挖矿/探索/守家/待命）并调用 `mc_mode`。
- **何时决策**：只在空闲时问，不是每秒问。默认冷却 30 秒，模型 90 秒没回应就放弃这轮。
- **断线兜底**：云端连不上时退化成固定轮转（砍木头 → 闲逛 → 找矿），不会站着发呆。
- **人工优先**：一旦在 QQ 或游戏里下了命令，自主调度立刻让位，不覆盖人的安排。

### mine 模式的停止条件

不加这层她会对着同一片区域无限挖。现在会在这些情况自动停：

| 条件 | 触发 |
|---|---|
| 挖够数 | `count` 参数（如 `count: 32`） |
| 超时 | `maxMinutes` 参数 |
| 背包快满 | 剩余 ≤ 2 格 |
| 天黑 | 自动，可用 `nightOff: false` 关掉 |
| 附近有敌对生物 | 8 格内，可用 `avoidHostiles: false` 关掉 |
| 血量 < 6 | 强制退出 mine/guard/wander |

### 名字识别

游戏名 `ChuXiaoxue`，中文别名 `初小雪`、`小雪`（插件配置 `bot_aliases`）。

### 现在的局限

- 没有"目标链"：一次只做一件事，做完再重问，不会自己规划"砍完木头去盖房子"。
- 不会睡觉、不会回家、不会躲雨。
- 死亡后不会主动捡装备。
- 每次决策都要调一次 LLM，一天频繁跑会有成本；`decideCooldownMs` 控制频率。

## 2026-10-26 夜跑复盘与改进

### 夜跑发现的问题

跑了两小时（18:07–19:41），29 条决策记录，暴露三个问题：

1. **60% 时间在待命**。`lastResult` 反复是"天黑了"，模型看到夜里就选 `idle` 干等。
2. **位置几乎不动**。连续 4-5 次询问都在同一个坐标。
3. **日志缺模型选择**。只有 `ask_model`，看不到模型最终选了什么。

### 已修复

| 问题 | 处理 |
|---|---|
| 夜里空转 | 加 `sleep` 模式：找床睡觉、天亮自动醒；没床就去地下挖矿 |
| 白天误睡 | `setMode('sleep')` 在白天直接拒绝，避免秒退 |
| 地下被"天黑"打断 | `_isNight` 判断前先看是否在地表，地下挖矿不受昼夜影响 |
| 模型不知道几点 | 意图消息带上 `dayProgress`（白天/夜晚 + 距天亮秒数）和是否在地下 |
| 日志不完整 | 新增 `model_choice`、`plan_step`、`manual_expired` 事件 |
| 成品方块误判 | 别名表把 `stone_bricks`/`cobblestone` 映射回 `stone`，`wood`/`tree` 映射到 `#minecraft:logs` |
| 模式切换后状态残留 | `_finishMine` 拆出通用 `_finishMode`，sleep 用自己的收工路径 |

### 目标链（mc_plan）

模型可以一次给 2-5 步计划，身体按序执行，**某一步失败会自动跳到下一步**。

实测案例：模型给出「白天砍木头 → 顺手挖点石头」，第一步砍了 16 秒遇到苦力怕自动收工，
计划没有中断，直接接上第二步。

### 当前局限

- 没有长期目标，每轮决策独立，不会累积"我要盖个房子"这种跨时段计划。
- 不会主动捡掉落物、整理背包、合成工具。
- 决策间隔 3 分钟（`decideCooldownMs`），一晚约 160 次 LLM 调用。
